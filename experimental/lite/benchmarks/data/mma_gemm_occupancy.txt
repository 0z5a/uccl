# Phase A: can the GEMM get past 2 resident blocks per SM?  Answer: no.
# T=2048, DeepSeek-V2-Lite grouped shape, cuBLAS = 49.4 TF/s on the same data.
#
# config                         regs   spill   bpsm       TF/s   vs.cub
  warp 64x32, ptxas choice        110       0      2       39.4    0.78x
  warp 64x32, __lb__(256,2)       108       0      2       39.4    0.78x
  warp 64x32, __lb__(256,3)        80     152      3       22.8    0.44x
  warp 64x32, __lb__(256,4)        64     428      4       11.4    0.20x
  warp 32x32 (128x64x32)           74       0      3       31.7    0.63x
  warp 32x32 (64x128x32)           80       0      3       31.5    0.63x
  warp 32x32, BK=64                80       0      1       31.3    0.61x
  warp 64x64 (128x256x32)         110       0      1       36.9    0.74x
#
# Spilling to buy occupancy is catastrophic: what spills is the accumulators,
# and every mma touches them. A smaller warp tile reaches 3 blocks cleanly but
# reads 61 B of smem per KFLOP against 64x32's 46, because each tile is re-read
# by more warps. A bigger warp tile has the better ratio and pays the 2nd block.
# 64x32 at 2 blocks is a local optimum; both directions out of it are downhill.
#
# XOR swizzle needs log2(BK/8) bits to decorrelate an ldmatrix phase's 8 rows:
#   BK=64 -> 3 bits, conflict-free, but 2-stage smem is 64 KB so bpsm=1 anyway
#   BK=32 -> 2 bits, rows 0 and 4 collide
# The only config the pad blocks (3 stages at 2 blocks) is the BK=32 case.
